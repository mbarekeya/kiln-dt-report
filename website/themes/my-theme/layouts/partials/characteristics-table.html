Characteristics Description
C1 System under study Lumber drying operations of a sawmill: green boards are grouped into lumber packages at the stacking line, stored in the yard, and dried in a batch kiln.
C2 Physical acting components kiln_controller: Controller running the kiln according to the drying schedule
C3 Physical sensing components mc_meter: Moisture meter used for the manual MC tests performed near the end of the cycle and after drying
th_sensor: Wet-bulb temperature sensor of the kiln; its data remain in the kiln controller, which is not connected to the DT
production_monitoring_system: Production monitoring system recording each package as it leaves the stacking line; updated every hour
ts_sensor: Dry-bulb temperature sensor of the kiln; its data remain in the kiln controller, which is not connected to the DT
C4 Physical-to-virtual interaction kiln_log_trans: Loads recorded manually by operators in the kiln log after drying: loading and drying times, loaded length and volume, length lost
mc_tests_trans: Results of the manual MC tests, recorded in the kiln log
package_records_trans: Package records (dimension, length, number of pieces, production date) collected automatically every hour from the production monitoring system
C5 Virtual-to-physical interaction Manual: loading plans and drying recommendations are applied by the operators. No command is sent to the kiln.
C6 DT services kiln_loading_optimization_service: computes one loading plan per lumber dimension (2x4, 2x6, 2x8) with a lexicographic MILP
mc_estimation_service: Estimates the MC of the load from the dry-bulb and wet-bulb temperatures of the kiln and compares it with the planned MC
monitoring_service: Web dashboard where operators request and validate loading plans, follow the drying cycle, and review recommendations
visualization_3d_service: 3D view of the kiln reproducing the arrangement of the validated load
C7 Twinning time-scale Package records collected automatically every hour; loading plans computed on request in 0.88 s on average; other requests answered in less than 0.06 s; simulated temperatures and MC estimates updated continuously during the drying cycle.
C8 Multiplicities One DT for the drying operations of one kiln, from the stacking line to the end of the drying cycle.
C9 Life-cycle stages Operation stage: preparation of kiln loads and follow-up of the drying cycle.
C10 DT models and data Model:
kiln_3d_model: 3D scene of the kiln with its lanes and lumber packages
kiln_schedule_model: Drying recipe of the sawmill: dry-bulb and wet-bulb temperature setpoints per phase
loading_milp_model: Column-based MILP: columns of four packages of the same length placed in the kiln lanes; maximizes the loaded volume, then prioritizes the oldest packages
mc_kinetics_model: MC kinetics of the lumber: dMC/dt = -k(MC - EMC) with Hailwood-Horrobin EMC

Data:
kiln_log_data: Kiln log of the sawmill: unused kiln length, MC at the final test, and cycle durations recorded for the studied kiln; used offline to set the cycle duration and calibrate the MC kinetics
package_data: Package records used to build the inventory available for kiln loading
simulated_temperature_data: Dry-bulb and wet-bulb temperatures generated by the simulator and provided by the data manager to the MC estimation service
C11 Tooling and enablers data_manager: Only accessor of the database: derives the available inventory from the package records and the validated loads, receives the kiln temperatures and the estimated MC during drying, and provides these data to the services
docker: Docker containers: one container per service
fastapi: Python FastAPI web server of the dashboard; relays operator requests to the services through RabbitMQ
godot: Godot game engine used for the 3D view of the kiln
highs: HiGHS MILP solver called through SciPy
simulator: Kiln simulator following the drying schedules of the sawmill; generates the dry-bulb and wet-bulb temperatures of the kiln, which the data manager provides to the MC estimation service
sqlite_database: SQLite database storing the package records, the validated loads, and the kiln state
production_data_collector: Collects the package records from the production monitoring system of the sawmill every hour
rabbit_mq: RabbitMQ message broker carrying all messages between the data manager, the services, and the 3D client
C12 DT constellation Services in Docker containers communicating only through RabbitMQ; a data manager is the only accessor of the SQLite database; Godot client on the host machine; package records collected from the production monitoring system of the sawmill.
C13 Twinning process and DT evolution Architecture based on ISO 23247. Inventory and loading side: digital shadow (automatic flow from the plant, decisions applied by operators). Kiln side: digital model (simulated temperatures and MC).
C14 Fidelity and validity considerations The inventory is built from production records and does not account for packages received from other mills. The drying constant k of the MC model is not calibrated, since the MC is not measured during drying.
C15 DT technical connection Automatic hourly collection of package records from the production monitoring system; AMQP (RabbitMQ) between services. The kiln controller is not connected to the DT.
C16 DT hosting/deployment Deployed locally on a laptop with Docker containers.
C17 Insights and decision making cycle_report: Report generated at the end of the drying cycle
drying_recommendation: Recommendations to the kiln operator during the cycle, who can review or override them
estimated_mc: Estimated MC and its deviation from the planned MC during the drying cycle
kiln_3d_view: 3D view of the validated load inside the kiln
loading_plans: One loading plan per dimension with its loaded volume, lane fill, and mean package age
validated_load: Loading plan selected and validated by the planner, then applied manually
monitoring_dashboard: Dashboard showing the loading plans, the estimated and planned MC, the drying progress, and recommendations
C18 Horizontal integration Integrated with the production monitoring system of the sawmill. The planning system and the kiln controller are not connected to the DT.
C19 Data ownership and privacy Production and kiln data belong to the industrial partner and are used within an academic collaboration.
C20 Standardization Architecture aligned with ISO 23247; communication via AMQP (RabbitMQ) with JSON payloads.
C21 Security and safety considerations No command is sent to the kiln, and all decisions remain with the operators.
